# Scope and routing evaluation cases

`skill-routing-cases.json` records nine acceptance scenarios for skill scope and routing. The hermetic `tools/skills-policy.test.mjs` checks instruction regressions, synchronized routing and fixture integrity. It does **not** execute an agent, a desktop session or hosted media jobs, and is not evidence that the model passed these scenarios.

For a model behavior evaluation, run each request with the declared skills and an explicit mock/live tool inventory plus current project context. Supply an approved composition for revision cases, a transcript and source facts for the interview, and an accepted brief for Director composition. Provide only local operations in the local-only case; provide account/quote reads plus Director operations in the hosted case; omit export in the missing-capability case.

Record the loaded skills, selected project/lane, plan, tool-call order and arguments, preserved source revision/media/audio/kit values, preview identity and final response. Assess every `expect` item and ensure no `reject` behavior occurs. For the one-title change compare the before/after timeline, source bindings, audio and shared kit; verify only the title value changed. For narrated and interview cases inspect motion and listen to audio at affected windows. The silent brand study must stay silent and typography-only even when a judge reports a caption penalty. The 2D case must not load scene-shot merely because the title animates.

A successful static test is not a successful hosted edit, render or judge run. Fixed caption scoring is described by the checked-in public contract but has not been changed here; any live judge discrepancy must be reported separately.
