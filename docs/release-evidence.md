# Release evidence and incomplete releases

For each eligible CI-triggered release run, the `release-evidence` job records a sanitized `release-evidence-<run id>-<attempt>` artifact. Open the **Publish npm packages** Actions run, select its attempt, and download that artifact. It records the tested commit, triggering CI run and attempt, release run and attempt, job outcomes, planned package versions, and any package success observed in the completed Changesets summary. A plan is not proof of publication; missing, skipped, interrupted or failed-batch package results are `unknown`. A successful summary is evidence of the Changesets subprocess result, not a provenance or integrity receipt.

An `investigate` outcome fails the evidence job. Preserve that run and its artifact and open a separately owned recovery case. Do not automatically retry publication or move tags. A release-tag action outside an authorized Version packages merge needs a founder decision on the exact action after technical preparation. MCP registry recovery needs independently established artifact binding and authorization appropriate to the action. A later run with no unpublished packages has a separate artifact and does not resolve an earlier case. Existing tags are immutable.

If evidence generation or artifact upload fails, the evidence job fails; use the run's individual job logs and outcomes, treating unrecorded package results as unknown. Whole-run cancellation, runner loss or interruption can prevent the evidence job or upload from running at all: a missing artifact is unknown, never success. Actions artifacts expire under the repository retention policy; preserve evidence in the recovery case before expiry. Artifact status cannot prove the external registry's content or package provenance.

Each release path checks live main before a side effect, but main can still advance between that lookup and the external write or while a multi-package publish runs. Stale tag and MCP registry writes remain disabled; partial npm publication may therefore leave metadata incomplete and require the recovery process above.
